# MCP tool inventory (A2, A5)

Agents never call GigSim, Upwork, a database or a file directly: every capability below is an MCP tool
with a schema and a test. Each node only sees the tools in its allowlist (`agent/config.yaml → tools.allowlist`).

`dry_run` flag that returns exactly what would be sent and what it costs; the approval screen shows that preview.

Portfolio server also exposes resource templates (`portfolio://case/{case_id}`, `portfolio://proposal/{proposal_id}`,
`portfolio://readme/{project}`, `portfolio://code/{project}`, `portfolio://review/{project}`, `portfolio://cv`) and prompt templates a freelancer would pick in Claude Desktop or Cursor
(e.g. "Answer a screening question from my portfolio"). See `mcp_servers/portfolio/README.md`.

## Third-party servers (not written by us)

| Server | Used for | Read / write | Auth | Trust rationale |
|---|---|---|---|---|
| Upwork official MCP (`https://mcp.upwork.com/mcp`) | live-mode marketplace adapter (`mcp_servers/marketplace/adapters/upwork_live.py`) | read + draft-only writes (user confirms on Upwork) | OAuth 2.1, tokens encrypted per user | Upwork's own server is the only sanctioned automated access to Upwork; every write is a draft the user must confirm there. |
| GitHub official MCP (`https://api.githubcopilot.com/mcp/x/repos/readonly`) | repo ingestion (`rag/ingest/github_mcp.py`) | read only (repos toolset, read-only URL) | personal access token from env | GitHub's own server, pinned to the read-only repos toolset, so it cannot change anything even if a prompt asked it to. |

## Tool design study (R&D question A)

40 tasks with known correct calls, same model (`qwen3:4b-instruct`, cheap tier), one tool-calling turn:
results in `evals/results/tool_granularity_cheap_shipped.json` (fine / coarse / shipped descriptions) and
`evals/results/tool_granularity_cheap_rewritten.json` (same 17 tools, rewritten descriptions). Discussion in the report, section 3.
