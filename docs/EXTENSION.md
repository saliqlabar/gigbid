# Signature extension: X1 Agency mode

**What it is.** A small agency of three freelancers (the AI/ML engineer, the full-stack developer and the data
analyst personas). With agency mode on (Settings → Agency mode), every new job is routed to the team member
whose portfolio fits it best, and that member's profile, evidence and voice are used for the whole bid.

**Why this one.** It reuses what GigBid already measures well (the Fit Matcher) and answers a question a real
agency has every day: who should take this job? It is also easy to get wrong cheaply (route by category),
which gives a clear baseline.

## How it works

```
new job ──► route_job (agent/agency.py)
              ├─ Fit Matcher for ai_ml        (Portfolio MCP, ai_ml's portfolio)   ─┐
              ├─ Fit Matcher for fullstack    (Portfolio MCP, fullstack's portfolio)├─► rank by (fit, strong matches)
              └─ Fit Matcher for data_analyst (Portfolio MCP, data_analyst's)      ─┘
                     │ best member below agency.min_fit_to_route? ─► skipped: "nobody on the team fits"
                     ▼
            bid graph for that member: their profile, their evidence, Writer voice line
            ("You are writing as <name>, <headline> ...", agent/nodes/writer.py `voice_line`)
```

* Routing calls the **same** production Fit Matcher once per member (in parallel), each through the Portfolio
  MCP server with that member's freelancer id, so a member's evidence never leaks into another's proposal.
* The routing decision (every member's fit, strong matches and missing skills, and the reason) is stored in
  the thread state (`agency_route`) and shown on the Job detail page.
* Config: `agency.members`, `agency.min_fit_to_route` in `agent/config.yaml`; switch: `agency_mode` user setting
  (worker passes persona `agency` to `start_bid`).

## How it is measured

`python -m evals.runners.agency_eval --per-persona 15` → `evals/results/agency_eval.json` (+ per-job detail).

* Ground truth: a dev-set job labelled *bid* in persona P's dev set belongs to member P (the dev set is labelled
  per persona from that persona's portfolio). Scams are excluded.
* Metric: routing accuracy (chosen member = gold member), per member and per job category, plus the confusion
  matrix and routing latency (three Fit Matcher calls).
* Baseline: the obvious cheaper rule, job category → member (AI/ML and Data science → ai_ml; Web development and
  Developer → fullstack; Data analysis → data_analyst; anything else → no one).

## Limits

* Gold labels only say which persona's dev set marked the job as a bid; a job two members could both do well is
  scored as a miss for whichever was not the labelled one, so accuracy is a lower bound on usefulness.
* Routing costs three Fit Matcher calls per job, which roughly triples the cheap-model cost of the fit step.
